# 第1回 `src/base32.ts`：接続コードの変換

このファイルは、**80ビットの秘密値（10バイト）と、16文字の接続コード（`79ZG-1HCH-5FJ0-GVFG` など）を相互に変換する**部品です。あわせて、人が手で入力したコードのゆれ（小文字、ハイフンの有無、`O` と `0` の打ち間違いなど）を吸収する関数もあります。

---

## 1. 前提知識

### 1-1. ビットとバイト

- **ビット**：0 か 1 の1桁
- **バイト**：8ビットのまとまり。0〜255 の数を表せる

数の書き方は3通りあり、このファイルではどれも出てきます。

| 書き方 | 例 | 意味 |
|---|---|---|
| 10進数 | `58` | 普段の数 |
| 16進数 | `0x3a` | 先頭が `0x`。1桁で4ビットを表す（`0`〜`9`、`a`〜`f`） |
| 2進数 | `0b00111010` | 先頭が `0b`。ビットをそのまま書く |

この3つは同じ数（58）です。1バイトは16進数2桁にちょうど収まるので、バイト列は16進数で書くのが一般的です。

### 1-2. Base32 とは

バイナリのデータを、人が読み書きできる文字だけで表す方法の1つです。

- **32種類の文字を使う**：32 = 2⁵ なので、**1文字でちょうど5ビット**を表せる
- **ビットの列を5ビットずつ区切り、それぞれを1文字に置き換える**

秘密値は80ビットなので、80 ÷ 5 = **16文字**になります。これが接続コードの長さです。

よく似た方式に Base64（64種類の文字、1文字6ビット）があります。Base64 は大文字と小文字を区別するので、手入力には向きません。

### 1-3. Crockford's Base32

Base32 にもいくつか種類があり、このアプリでは Douglas Crockford が考案した方式を使っています。**人が読み書きすることを重視した**方式で、次の特徴があります。

- 使う文字：`0123456789ABCDEFGHJKMNPQRSTVWXYZ`（数字10種＋英大文字22種）
- **使わない文字**：`I`、`L`、`O`、`U`
  - `I` と `L` は `1` と、`O` は `0` と見間違えやすい
  - `U` は、うっかり不適切な英単語ができるのを避けるために除かれている
- 読み取るときは、`O` を `0` に、`I` と `L` を `1` にみなす。小文字も大文字とみなす

### 1-4. ビット演算

数をビットの列とみなして操作する演算です。ここでは 8ビットの例で説明します。

| 演算 | 意味 | 例 |
|---|---|---|
| `a << n` | 左に n ビットずらす（右に 0 が入る） | `0b00000111 << 2` → `0b00011100` |
| `a >>> n` | 右に n ビットずらす（はみ出たビットは捨てる） | `0b00111010 >>> 3` → `0b00000111` |
| `a \| b` | ビットごとの OR（どちらかが 1 なら 1） | `0b11000000 \| 0b00000011` → `0b11000011` |
| `a & b` | ビットごとの AND（両方 1 なら 1） | `0b00111010 & 0b00011111` → `0b00011010` |

特によく使う組み合わせが2つあります。

- **`& 31` で下位5ビットだけを取り出す**：31 は 2進数で `11111` なので、AND をとると下5ビット以外が0になります。`& 0xff`（`11111111`）なら下位8ビット、`& 0xffff` なら下位16ビットです。この使い方を「マスク」と呼びます。
- **`(x << 8) | b` で右端に8ビットを継ぎ足す**：x を左に8ビットずらして空いた場所に、b の8ビットをはめ込みます。

`>>` と `>>>` はどちらも右シフトですが、`>>>` は常に左端に 0 を入れます。`>>` は数が負のとき左端に 1 を入れるため、ビットの列として扱うときは `>>>` を使うのが安全です。

| 行 | 説明 |

| 行 | 説明 |
|---|---|
| 18 | 最後に5ビットに満たない余りがあれば、右側に0を足して5ビットにしてから文字にする。`buffer << (5 - bits)` で余りのビットを左に寄せ、足りない分を0で埋める |
| 19 | 結果を返す |

**18行目は、接続コードでは実際には使われません。** 秘密値は80ビットで、5でちょうど割り切れるからです。どんな長さのバイト列でも正しく変換できるよう、念のため書いてあります。

#### 具体例：`0x3a, 0x7f` の2バイトを変換する

```
0x3a = 0011 1010
0x7f = 0111 1111
つなげると：00111 01001 11111 1
            ─┬── ──┬── ──┬── ┬
             7     9     31  1（余り）
```

コードの動きを追うと次のとおりです。

| 時点 | `buffer`（2進数） | `bits` | 取り出す5ビット | 文字 |
|---|---|---|---|---|
| 1バイト目を入れた | `00111010` | 8 | `00111` = 7 | `7` |
| 　 | 　 | 3 | （5未満なので次へ） | |
| 2バイト目を入れた | `0011101001111111` | 11 | `01001` = 9 | `9` |
| 　 | 　 | 6 | `11111` = 31 | `Z` |
| 　 | 　 | 1 | （5未満なので次へ） | |
| 18行目（余り） | 余り `1` → `10000` | | `10000` = 16 | `G` |

結果は `79ZG` です。表の2行目で `bits` が3のとき、`buffer` の右端3ビット（`010`）はまだ文字になっていません。次のバイトを継ぎ足したあとで、`01001` の先頭3ビットとして使われます。

#### 補足：なぜ `& 0xffff` が必要か

`& 0xffff` がないと、バイトを継ぎ足すたびに `buffer` が8ビットずつ長くなり続けます。JavaScript のビット演算は32ビットの整数で行われるので、4バイト目あたりで左端のビットがあふれて、数が負になったり値が壊れたりします。

実際に必要なのは「まだ文字にしていないビット」だけです。最大でも、余り4ビット＋新しい8ビット＝12ビットしかありません。そこで、`& 0xffff` で下位16ビットだけを残し、古いビットを捨てています。12ビットより大きい16ビットにしてあるのは、余裕を持たせるためです。

### 40〜47行目：`normalizeCode()`（手入力のゆれを直す）

```ts
/** 手入力のゆれを吸収する（F-15） */
export function normalizeCode(input: string): string {
  return input
    .toUpperCase()
    .replace(/[\s\-_.・ー－‐]/g, '')
    .replace(/O/g, '0')
    .replace(/[IL]/g, '1');
}
```

文字列の処理をつなげて順に行う書き方です（メソッドチェーン）。前の処理の結果に、次の処理を行います。

| 行 | 処理 | 例 |
|---|---|---|
| 43 | すべて大文字にする | `'7k3q-lo'` → `'7K3Q-LO'` |
| 44 | 区切りに使われがちな記号を消す（下で説明） | `'7K3Q-LO'` → `'7K3QLO'` |
| 45 | `O`（オー）を `0`（ゼロ）に置き換える | `'7K3QLO'` → `'7K3QL0'` |
| 46 | `I` と `L` を `1` に置き換える | `'7K3QL0'` → `'7K3Q10'` |

先に大文字にしているので、45〜46行目では小文字の `o`・`i`・`l` を考えなくて済みます。

#### 正規表現の読み方

`/…/g` は**正規表現**（文字のパターン）です。`replace` で「パターンに当てはまる部分を置き換える」ために使います。

| 部分 | 意味 |
|---|---|
| `/` と `/` | 正規表現の始まりと終わり |
| `g` | 当てはまる部分を**すべて**置き換える（`g` がないと最初の1か所だけ） |
| `[…]` | 中に書いた文字の**どれか1文字** |
| `\s` | 空白文字（半角スペース、全角スペース、タブ、改行など） |
| `\-` | ハイフン。`[ ]` の中では `-` が「範囲」（`a-z` など）の意味になるため、`\` を付けて文字そのものとして扱う |
| `_` `.` | アンダースコアとピリオド |
| `・` | 中黒 |
| `ー` | 長音記号。日本語入力のままハイフンを打つとこれになりやすい |
| `－` | 全角のハイフンマイナス |
| `‐` | ハイフン（Unicode のもう一つのハイフン） |

#### 気づいた点：全角の英数字には対応していない

日本語入力のまま `ｇ４` のように**全角の英数字**を打つと、そのまま残ります。

```
normalizeCode(' 78z0-ｇ4ー lo1i ')  →  '78Z0Ｇ41011'
                                           ^ 全角のＧが残る
```

この場合、参加画面で「使えない文字が含まれています：Ｇ」と表示されます。接続はできませんが、原因は分かるようになっています。

全角を半角に直すには、43行目の前に `.normalize('NFKC')` を1つ足せば済みます（Unicode の正規化。全角英数字を半角に変換する）。要件 F-15 には全角の扱いが書かれていないので、今は対応していません。

### 49〜52行目：`invalidChars()`（使えない文字を探す）

```ts
/** 正規化後の文字列のうち、使えない文字の一覧 */
export function invalidChars(normalized: string): string[] {
  return [...new Set([...normalized].filter((ch) => !ALPHABET.includes(ch)))];
}
```

1行に処理が詰まっているので、内側から順に分解します。`'78Z0UUA!'` を例にします。

| 順番 | 部分 | 結果 |
|---|---|---|
| 1 | `[...normalized]` | 文字列を1文字ずつの配列にする：`['7','8','Z','0','U','U','A','!']` |
| 2 | `.filter((ch) => !ALPHABET.includes(ch))` | `ALPHABET` に含まれない文字だけを残す：`['U','U','!']` |
| 3 | `new Set(…)` | 重複を取り除いた集合にする：`{'U','!'}` |
| 4 | `[...(集合)]` | 集合を配列に戻す：`['U','!']` |

使われている書き方：

| 書き方 | 意味 |
|---|---|
| `...`（スプレッド構文） | 文字列や集合の中身を1つずつ展開する。`[...x]` で「x の中身を並べた配列」になる |
| `(ch) => …` | アロー関数。名前のない小さな関数を短く書く方法。`function (ch) { return …; }` とほぼ同じ |
| `.filter(関数)` | 配列の要素ごとに関数を呼び、`true` を返した要素だけを残す |
| `!` | 否定。`includes` が `true`（含まれる）なら `false` になる |
| `Set` | 重複を許さない集合。同じ値を何度入れても1つになる |

`[...normalized]` で文字列を分けているのは、`normalized.split('')` よりも安全だからです。絵文字のような特殊な文字（2つの部品でできている文字）も、1文字として正しく分けられます。

この関数は、エラーメッセージに「使えない文字が含まれています：U !」と表示するために使います。

### 54〜56行目：`formatCode()`（4文字ごとにハイフンを入れる）

```ts
export function formatCode(code: string): string {
  return code.match(/.{1,4}/g)?.join('-') ?? '';
}
```

| 部分 | 意味 |
|---|---|
| `/.{1,4}/g` | 正規表現。`.` は任意の1文字、`{1,4}` は「1〜4回のくり返し」。`g` で、文字列の先頭から順に、当てはまる部分をすべて探す。結果として、4文字ずつ（最後は余りの1〜3文字）に区切られる |
| `code.match(…)` | 当てはまった部分の配列を返す。`'ABCDEFG'` なら `['ABCD', 'EFG']`。**1つも当てはまらない（空の文字列の）ときは `null` を返す** |
| `?.join('-')` | `?.` は「左が `null` か `undefined` なら、ここで止めて `undefined` にする」。`null` でなければ `join('-')` で、配列の要素を `-` でつなげて1つの文字列にする |
| `?? ''` | `??` は「左が `null` か `undefined` なら、右の値を使う」。空の文字列を渡したときに、`undefined` ではなく `''` を返すため |

| 入力 | 結果 |
|---|---|
| `'79ZG1HCH5FJ0GVFG'` | `'79ZG-1HCH-5FJ0-GVFG'` |
| `'ABCDEFG'` | `'ABCD-EFG'` |
| `''` | `''` |

`?.` と `??` がなければ、空の文字列で `null.join(…)` を呼んでエラーになってしまいます。`tsconfig.json` の `strict` によって、`match` の戻り値が `null` になりうることを型チェックが指摘してくれるので、このような書き方が必要になります。

## 5. 理解チェック

1. 接続コードが16文字なのはなぜですか。
2. `ALPHABET` に `U` が含まれないのはなぜですか。また、`normalizeCode()` で `U` を別の文字に置き換えていないので、`U` を入力するとどうなりますか。
3. `encodeBase32()` の18行目（余りの処理）が、接続コードの変換では実行されないのはなぜですか。
4. `decodeBase32()` で、`while` ではなく `if` で足りるのはなぜですか。
5. `formatCode('')` で `?.` と `??` を使わずに `code.match(/.{1,4}/g).join('-')` と書くと、どうなりますか。
6. `(0b00111010 >>> 3) & 31` の値を計算してください。

<details>
<summary>答え</summary>

1. 秘密値が80ビットで、Base32 は1文字で5ビットを表すため。80 ÷ 5 = 16。
2. うっかり不適切な英単語ができるのを避けるため（Crockford の方式の決まり）。`U` を入力すると、`invalidChars()` で使えない文字として見つかり、「使えない文字が含まれています：U」と表示される。
3. 80ビットは5でちょうど割り切れるので、最後に余りのビットが残らないため。
4. 1文字につき5ビットしか増えず、取り出すときは8ビット減る。8ビット以上たまった状態で1バイト取り出すと、必ず8ビット未満に戻る（最大で 7＋5＝12 → 取り出して 4）。そのため、1文字ごとに取り出すのは最大1回で済む。
5. 空の文字列では `match` が `null` を返すので、`null.join(…)` を呼ぼうとしてエラー（例外）になる。また、型チェックでも「`null` の可能性がある」としてエラーになる。
6. `0b00111010 >>> 3` = `0b00000111`、`& 31`（`0b11111`）で `0b00111` = **7**。`encodeBase32` の具体例で、最初の文字 `7` を作った計算と同じ。

</details>
